01THE FOUNDATION OF LANGUAGE
QUESTION 01 · THINK BEFORE YOU ANSWER
为什么 LLM 需要一个有限的 Token 词表？
世界上的文字组合几乎无限，但模型不可能为每一个新词都建立一个独立编号。
假设让 AI 学习互联网上所有的文字。每天都有新词、人名、网络用语不断出现。怎样让 AI 认识尽可能多的词，同时又不必为每一个新词都单独创建一个编号？
✓ 正确答案：C · 有限词表，无限组合Tokenizer 将文本切分为 Token，并映射为有限 Vocabulary 中的 Token ID。遇到未见过的新词，也可以通过已有 Token 组合表示。Aha Moment：模型不需要认识世界上每一个词，但需要一套能够组合表达无限语言的基本符号。
Token 不只是文本切分，它定义了模型认识语言的基本粒度。

02THE HIDDEN DETAIL OF TOKENIZATION
QUESTION 02 · LOOK CLOSER
你看到的单词，就是模型看到的 Token 吗？
一个空格，可能就改变 Token 的身份。你以为的单词边界，不一定是模型的 Token 边界。
下面两个英文字符串，哪个才可能是 GPT 等商业大模型 Tokenizer 词表中的一个独立 Token？
STRING A · 前面有一个空格" The"
STRING B · 前面没有空格"The"
✓ 正确答案：C · 空格也可能属于 Token对于支持这两个独立词表项的 Tokenizer，" The" 和 "The" 是两个不同的字符序列，可以分别映射到不同 Token ID。空格并非总是被忽略，它可能直接成为 Token 的一部分。Aha Moment：Token 不是我们肉眼理解的单词，而是 Tokenizer 根据具体规则切分出来的离散符号单元。
模型认识的不是你眼中的单词，而是 Tokenizer 定义的离散符号。
QUESTION 02 / 03 · A SPACE CAN CHANGE THE TOKEN
03THE ARCHITECTURAL TRADE-OFF
QUESTION 03 · THINK LIKE AN ARCHITECT
Token 词表扩大 10 倍，模型就更高效吗？
Token 词表设计，不只是语言问题，更是参数规模、上下文容量与计算效率之间的架构权衡。
假设两个 LLM 使用相同的 Transformer 架构、相同的隐藏维度和训练数据：模型 A 的词表有 32K 个 Token；模型 B 的词表有 320K 个 Token，更多常见词语可能直接用一个 Token 表示。你认为最可能发生什么？
✓ 正确答案：C · 参数规模与序列效率的权衡假设隐藏维度 D=4,096，输入 Embedding 矩阵参数量为 V×D：
模型 A · 32K Vocabulary约 1.31 亿32,000 × 4,096 个参数
模型 B · 320K Vocabulary约 13.11 亿320,000 × 4,096 个参数
更大的词表可能让文本切分更紧凑，减少序列长度 N；标准全注意力的序列计算量通常随 N² 增长。但更大的词表也增加 Embedding 参数、输出词表投影与 Softmax 等成本。 Aha Moment：词表设计是在有限的符号空间、模型参数规模和文本计算效率之间寻找平衡。词表越大，不代表模型越聪明或端到端推理一定越快。
Tokenizer 不只是文本预处理，它是影响模型计算效率的重要架构设计。

DETERMINISTIC MODEL

先算清楚：安全库存

SS = Z × σd × √L
√L 的含义：L 期需求标准差 = σd × √L；需求越波动、提前期越长、服务水平越高，安全库存越大。
SS安全库存：抵御波动的缓冲
Z服务水平对应的分位数
σd每周期需求的标准差
L提前期（以周期计）
成立前提
需求可变，提前期恒定
各周期需求独立同分布
需求近似正态
目标服务水平固定
常用 Z 值
90% 1.28 95% 1.65 97.5% 1.96 99% 2.33
算例：95% · σd=120 · L=4 → 1.65×120×2 = 396 件
毫秒级 · 可复算 · 可解释 · 可审计
适用稳定需求 · 固定交期 · 需要可解释 / 可审计
不适用间歇需求 · 多峰 · 强促销 · 新品冷启动
常见变体
提前期可变，需求恒定SS = Z × d × σL
两者均可变（独立）SS = Z × √(L × σd² + d² × σL²)

CAN DEEP LEARNING REPLACE IT?

环节传统做法DL 的角色与边界
需求波动 σd预测精度历史标准差推荐 · LSTM / Transformer / TFT 预测分布或分位数
提前期 L供应不确定性恒定或简单分布可以 · 建模供应商交期的非线性与长尾

整体 SS 决策端到端公式计算谨慎 · 需大量数据，难解释、难审计
公式本身解析解SS = Z × σd × √L不建议 · 假设成立时公式更稳、更透明
不建议整体替换：小样本公式更稳 · 可审计 · 冷启动有兜底 · 维护成本低 · 稳定场景增益有限
03 · 更实际的落地路线
A
DL 提供输入，公式做决策 性价比最高

DL 预测提前期内需求分位数，SS = P95 − 期望需求；保留可解释框架。

B
分位数回归直接建模 推荐

TFT / DeepAR / N-BEATS 直接输出 P95，天然处理非正态、间歇、多峰与多季节性。

C
端到端库存优化 谨慎

RL / 数学规划 + 预测，适合多 SKU、多级、有约束场景；样本效率低，难解释。

一句话：DL 优化输入，公式守住决策；混合方案性价比最高。头部 SKU 用 DL，长尾 / 冷启动用公式兜底；高影响确定值不交给 LLM 自由生成。
