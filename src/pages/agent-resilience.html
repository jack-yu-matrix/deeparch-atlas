01 / CONTEXT

为什么 LLM 调用需要一套独立的治理体系？

传统 HTTP 服务通常关注请求成功率和响应时间；LLM 流式服务还必须管理生成过程中的时间、连接和资源。

01

响应时间不可预测

模型排队、Prompt 长度、推理负载都会影响首 Token 和完整生成时间。

02

连接长期占用

SSE 连接可能持续数秒甚至数分钟，消耗 Web 容器、网络和模型并发资源。

03

故障影响面更大

Provider 故障或模型拥塞可能导致大量请求堆积，并产生级联超时。

治理目标

让系统在模型慢、模型故障、流量突增时，依然能够快速响应、隔离故障并优雅降级。

PROBLEM SPACE03 / 20
03 / DESIGN PRINCIPLES

总体设计原则

保护用户体验

优先保证首 Token 响应速度，避免用户长时间等待而没有反馈。

保护系统资源

控制并发和请求速率，避免慢请求持续占用连接和线程。

隔离模型故障

通过熔断和主备模型降低单一 Provider 故障的影响范围。

尊重流式语义

已输出内容后不切换模型，避免拼接两次生成结果造成语义错乱。

核心思想：在请求进入模型之前做流量控制，在模型生成过程中做时间治理，在故障发生时做隔离与降级。

06 / SSE & REACTOR

SSE 流式机制：Flux 是核心载体

SSE 是传输协议

Server-Sent Events 基于 HTTP 长连接，由服务端持续向客户端推送事件。

Flux 是数据流抽象

Spring WebFlux 使用 Reactor Flux 表示 0 到 N 个异步数据项，可以在订阅、取消、错误和完成时执行治理逻辑。

data: 你好

data: ，欢迎使用

data: 大模型服务

event: done
data: [DONE]

示意：每个 SSE event 都是独立消息。实际接口可使用 ServerSentEvent 对象表达 event、id、retry 和 data。

关键点：SSE 连接建立不等于模型已经返回首 Token。HTTP 200、响应头和心跳事件都不能作为 TTFT 成功的判据。

SSE & REACTOR07 / 20
07 / TTFT DEFINITION

TTFT：首 Token 时间到底测量什么？

TTFT（Time To First Token）衡量模型从收到请求到产生第一个有效内容的等待时间，是流式体验最重要的指标之一。

请求订阅开始首个有效内容块流结束
TTFT
后续生成时间

计时起点

一次模型调用真正开始订阅的时刻，而不是 Controller 创建对象的时刻。

计时终点

收到第一个有效文本内容块的时刻。空字符串、元数据和结束标记不计入。

实现注意：Spring AI 的 content() 通常返回文本 chunk，不保证每个 chunk 严格等于模型 tokenizer 的一个 Token。因此应用层测量更准确的名称是 First Content Chunk Latency，可作为 TTFT 近似指标。

TTFT DEFINITION08 / 20
08 / TTFT CIRCUIT BREAKER

TTFT 熔断：不仅是一个超时操作

TTFT Timeout

单次请求的首内容等待时间超过阈值，就取消该次上游调用并触发超时处理。

单请求保护

TTFT Circuit Breaker

统计一段时间内的首内容慢调用比例或失败率。当模型持续变慢时，阻止新请求继续进入故障 Provider。

系统级保护

推荐判定模型

指标示例阈值含义
TTFT 慢调用阈值5 秒超过该时间视为慢调用
慢调用率阈值50%滑动窗口内慢调用比例达到阈值
最小样本数20 次避免样本太少导致误判
OPEN 等待时间30 秒暂时拒绝新请求

以上是示例参数，实际阈值应根据模型、地域、Prompt 长度、业务 SLA 和压测结果确定。

09 / CIRCUIT BREAKER STATE MACHINE

熔断器的三种状态

CLOSED

正常放行

持续收集请求结果、慢调用比例和失败率。

OPEN

快速拒绝

达到熔断条件后拒绝调用，避免请求继续压向故障模型。

HALF_OPEN

探测恢复

允许少量试探请求，成功后关闭熔断，失败则重新打开。

注意：熔断器应该围绕“首内容块阶段”记录 TTFT 慢调用，而不是将整个 Flux 生命周期当成 TTFT。完整生成耗时可以由独立指标或另一个治理策略负责。

10 / TRAFFIC CONTROL

限流与并发隔离：保护模型，也保护应用

RateLimiter · 请求速率

RPS

限制单位时间内允许进入模型的请求数量，控制 Provider 的调用速率与成本。

适合：配额、突发流量、供应商 RPM 限制。

Bulkhead · 并发隔离

N

限制同时运行的模型流式任务数量，防止长连接无限占用系统资源。

适合：慢请求、连接池保护、模型并发上限。

FALLBACK STRATEGY12 / 20
12 / TIMEOUT STRATEGY

三层超时：覆盖完整生成生命周期

01

TTFT Timeout

限制等待首个有效内容块的时间。

例如：5 秒

02

Idle Timeout

限制相邻两个内容块之间的最大空闲时间。

例如：15 秒

03

Generation Deadline

限制整个模型生成任务的最大持续时间。

例如：120 秒

为什么不能只设置一个 Timeout？

首 Token 慢、生成中途卡住、持续输出但整体过长，是三种不同的故障表现。它们需要独立阈值、独立指标和不同处理方式。

请求开始 ── TTFT ── 首内容块 ── Idle Gap 检测 ── 内容块 ... ── Deadline
     │                 │              │                   │
     └─────────────────┴──────────────┴───────────────────┘
                         全程受总时限约束

13 / FAILURE HANDLING

异常处理与 SSE 生命周期

场景系统动作客户端表现
主模型首内容超时取消主模型，尝试备用模型继续等待内容
备用模型也失败终止流，记录错误收到 error 事件
首内容后 Provider 异常不再切换模型，终止当前流收到 error 事件
Idle Timeout取消上游订阅收到超时错误
客户端断开取消上游订阅并释放许可连接结束
Generation Deadline取消流并记录超时收到错误或结束事件

重要：HTTP 响应头一旦发送，不能再把已经返回的 HTTP 200 改成 500。因此流式阶段的业务异常应通过 SSE error 事件表达，而不是试图修改 HTTP Status。

核心代码模块如何分工？

模块职责关键实现
LlmStreamController对外提供 SSE APIFlux / ServerSentEvent
LlmStreamingService调用编排、主备路由ChatClient.stream()

核心设计原则：Controller 不负责模型治理；Service 不负责 HTTP 细节；超时与熔断策略通过独立组件管理。

CODE DESIGN15 / 20
15 / STREAMING FLOW

主模型超时后的时序过程

1. Client → Controller

客户端发起 SSE 请求，服务端建立流式响应。

2. Controller → Service

Service 进行速率限制、熔断检查和并发隔离。

3. Service → Primary Provider

开始订阅主模型 Flux，同时启动 TTFT 计时。

4. TTFT Timeout

超过阈值仍没有有效内容块，取消主模型订阅。

5. Fallback Provider

在尚未输出有效内容的前提下调用备用模型。

6. First Content Chunk

备用模型返回首内容，停止 TTFT 计时并继续输出。

7. Stream Complete

正常完成，记录指标并释放资源。

指标名称监控意义告警方向

17 / CONFIGURATION

核心参数配置示例

llm:
  primary-model: primary
  fallback-model: fallback

  timeout:
    first-content: 5s
    idle: 15s
    generation: 120s

  resilience:
    rate-limiter:
      limit-for-period: 30
      limit-refresh-period: 1s

    bulkhead:
      max-concurrent-calls: 50
      max-wait-duration: 0

    ttft-breaker:
      slow-call-duration-threshold: 5s
      slow-call-rate-threshold: 50
      sliding-window-size: 50
      minimum-number-of-calls: 20
      wait-duration-in-open-state: 30s

这是配置结构示例，并非 Spring AI 或 Resilience4j 的全部原生属性。需要在配置类中映射到对应实例；尤其 TTFT 慢调用统计需要针对首内容阶段设计，不能直接把完整 Flux 的生命周期作为 TTFT。

18 / PRODUCTION READINESS

生产环境落地检查清单

网络与代理

关闭 Nginx SSE 响应缓冲；配置合理的 read timeout；验证 HTTP/1.1 长连接和代理链路。

资源生命周期

客户端取消必须传播到上游；释放 Bulkhead 许可；避免线程池和连接池泄漏。

模型策略

主备模型应明确能力、价格、上下文长度和地域差异；防止重复计费和无限重试。

压测与验证

覆盖慢首 Token、流中断、模型限流、客户端断开、并发突增、备用模型失败等场景。

实际配置应结合入口网关、负载均衡器和模型服务的超时策略统一规划。
